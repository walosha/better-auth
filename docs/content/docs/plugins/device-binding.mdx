# Device Binding

The Device Binding plugin provides enhanced security by binding user sessions to specific devices, preventing unauthorized access even if credentials are compromised. It implements device fingerprinting, trust management, and phishing-resistant authentication flows.

## Installation

```bash
npm install better-auth
```

## Setup

Add the device binding plugin to your Better Auth configuration:

```ts
import { betterAuth } from "better-auth"
import { deviceBinding } from "better-auth/plugins"

export const auth = betterAuth({
  database: {
    // your database config
  },
  plugins: [
    deviceBinding({
      // optional configuration
    })
  ]
})
```

## Configuration

### Options

The device binding plugin accepts the following configuration options:

```ts
interface DeviceBindingOptions {
  /**
   * Duration in days for how long a device remains trusted
   * @default 30
   */
  trustDuration?: number;
  
  /**
   * Maximum number of trusted devices per user
   * @default 3
   */
  maxTrustedDevices?: number;
  
  /**
   * Whether to require device verification for new devices
   * @default true
   */
  requireDeviceVerification?: boolean;
  
  /**
   * Custom device fingerprint generator
   */
  generateDeviceFingerprint?: (context: any) => Promise<string> | string;
  
  /**
   * Enable automatic device registration on login
   * @default false
   */
  autoRegisterDevice?: boolean;
  
  /**
   * Block all new devices except for first-time users
   * @default true
   */
  strictMode?: boolean;
  
  /**
   * TOTP verification function for trusting devices
   */
  verifyTOTP?: (userId: string, code: string) => Promise<boolean>;
  
  /**
   * OTP verification function for trusting devices
   */
  verifyOTP?: (userId: string, code: string) => Promise<boolean>;
  
  /**
   * Send OTP function for device verification
   */
  sendOTP?: (userId: string, deviceInfo: DeviceInfo) => Promise<string>;
}
```

### Example Configuration

```ts
export const auth = betterAuth({
  database: {
    // your database config
  },
  plugins: [
    deviceBinding({
      trustDuration: 30, // 30 days
      maxTrustedDevices: 5,
      requireDeviceVerification: true,
      strictMode: true,
      sendOTP: async (userId, deviceInfo) => {
        // Send OTP via your preferred method
        const otp = generateRandomOTP();
        await sendEmail(userId, `Your device verification code: ${otp}`);
        return otp;
      }
    })
  ]
})
```

## Client Usage

### Setup Client

```ts
import { createAuthClient } from "better-auth/client"
import { deviceBindingClient } from "better-auth/client/plugins"

const client = createAuthClient({
  plugins: [
    deviceBindingClient({
      autoRegisterDevice: false,
      strictMode: true,
      onDeviceVerificationRequired: async (data) => {
        // Handle device verification UI
        console.log("Device verification required:", data.message);
      },
      onOTPRequired: async (data) => {
        // Handle OTP input UI
        const otp = prompt("Enter OTP:");
        // Verify OTP...
      }
    })
  ]
})
```

### Register Device

```ts
// Register device with OTP verification
const result = await client.deviceBinding.register({
  email: "user@example.com",
  deviceInfo: {
    userAgent: navigator.userAgent,
    screenResolution: `${screen.width}x${screen.height}`,
    timezone: Intl.DateTimeFormat().resolvedOptions().timeZone,
  },
  step: "request" // First step: request OTP
});

// Verify OTP
const verified = await client.deviceBinding.register({
  email: "user@example.com",
  step: "verify",
  otp: "123456",
  trustDevice: true
});
```

### Trust Device

```ts
// Trust device using TOTP
await client.deviceBinding.trust({
  deviceId: "device-123",
  totpCode: "123456"
});

// Trust device using OTP
await client.deviceBinding.trust({
  deviceId: "device-123", 
  otpCode: "654321"
});
```

## Security Features

### Device Fingerprinting

The plugin generates unique device fingerprints using:

- User agent string
- Screen resolution
- Timezone
- Language preferences
- Platform information
- Hardware concurrency
- Touch points
- Color depth
- Pixel ratio

### Strict Mode

When `strictMode` is enabled:

- New devices are blocked by default
- Only trusted devices can access accounts
- First device is automatically trusted
- Subsequent devices require verification

### Trust Management

- Devices expire after the configured trust duration
- Maximum number of trusted devices is enforced
- Untrusted devices can be promoted with 2FA
- Device trust can be revoked at any time

### Rate Limiting

Built-in rate limiting protects against abuse:

- Device registration: 3 requests per minute
- Trust operations: 3 requests per minute
- General endpoints: 15 requests per 10 seconds

## Hooks and Middleware

The plugin automatically integrates with authentication flows:

### Login Hooks

- Checks device trust status on login
- Blocks untrusted devices in strict mode
- Updates device last seen timestamp
- Manages device binding cookies

### Session Management

- Validates device binding on each request
- Refreshes device trust expiration
- Clears sessions on untrusted devices

## Error Handling

### Common Error Codes

| Code | Description | Solution |
|------|-------------|----------|
| `DEVICE_NOT_REGISTERED` | Current device not found | Register the device |
| `DEVICE_NOT_TRUSTED` | Device exists but not trusted | Trust the device with 2FA |
| `MAX_DEVICES_REACHED` | Too many trusted devices | Remove unused devices |
| `INVALID_OTP` | OTP verification failed | Check code and retry |
| `DEVICE_EXPIRED` | Device trust expired | Re-trust the device |

      sendOTP: async (userId, deviceInfo) => {

## Advanced Usage

### Custom Device Fingerprinting

```ts
import { deviceBinding } from "better-auth/plugins"
import { createHash } from "crypto"

export const auth = betterAuth({
  plugins: [
    deviceBinding({
      generateDeviceFingerprint: async (context) => {
        const headers = context.headers;
        const clientIP = headers.get("x-forwarded-for") || "unknown";
        const userAgent = headers.get("user-agent") || "";
        
        // Create custom fingerprint
        const fingerprint = `${clientIP}-${userAgent}-${Date.now()}`;
        const hash = createHash("sha256").update(fingerprint).digest("hex");
        
        return hash;
      }
    })
  ]
})
```

### Custom Hook Example

```ts
import { useState, useEffect } from "react"
import { client } from "./auth-client"

export function useDeviceBinding() {
  const [devices, setDevices] = useState([]);
  const [isLoading, setIsLoading] = useState(false);
  
  useEffect(() => {
    loadDevices();
  }, []);
  
  const loadDevices = async () => {
    setIsLoading(true);
    try {
      const result = await client.deviceBinding.list();
      setDevices(result.devices);
    } catch (error) {
      console.error("Failed to load devices:", error);
    } finally {
      setIsLoading(false);
    }
  };
  
  const trustDevice = async (deviceId: string, totpCode: string) => {
    try {
      await client.deviceBinding.trust({ deviceId, totpCode });
      await loadDevices(); // Refresh list
    } catch (error) {
      console.error("Failed to trust device:", error);
    }
  };
  
  const removeDevice = async (deviceId: string) => {
    try {
      await client.deviceBinding.remove({ deviceId });
      await loadDevices(); // Refresh list
    } catch (error) {
      console.error("Failed to remove device:", error);
    }
  };
  
  return {
    devices,
    trustDevice,
    removeDevice,
    isLoading,
    refresh: loadDevices
  };
}
```

## Migration Guide

### Existing Users

For applications with existing users, consider this migration strategy:

1. **Gradual Rollout**: Start with `strictMode: false` and `autoRegisterDevice: true`
2. **Notification Period**: Notify users about the new security feature
3. **Enforcement**: After a grace period, enable `strictMode: true`

```ts
// Phase 1: Soft rollout
deviceBinding({
  strictMode: false,
  autoRegisterDevice: true,
  requireDeviceVerification: false
})

// Phase 2: After user notification
deviceBinding({
  strictMode: true,
  autoRegisterDevice: true,
  requireDeviceVerification: true
})
```

### Database Migration

If you need to migrate existing users:

```sql
-- Add device binding fields to existing users
ALTER TABLE user ADD COLUMN device_binding_enabled BOOLEAN DEFAULT TRUE;
ALTER TABLE user ADD COLUMN has_registered_device BOOLEAN DEFAULT FALSE;

-- Auto-register devices for active sessions
-- This should be done programmatically based on your session data
```

## Troubleshooting

### Device Not Recognized

If users frequently see "device not recognized" errors:

1. Check if cookies are enabled
2. Verify fingerprinting stability
3. Consider less strict fingerprinting
4. Increase `trustDuration`

### OTP Not Received

Common OTP delivery issues:

1. Check spam folders
2. Verify email/SMS provider configuration
3. Implement retry mechanisms
4. Add delivery status tracking

### Performance Considerations

- Device fingerprinting adds ~10-20ms per request
- Database queries are optimized with indexes
- Consider caching device status for high-traffic apps
- Rate limiting prevents abuse

## Security Considerations

### Best Practices

1. **Regular Cleanup**: Remove expired devices periodically
2. **Audit Logging**: Log device trust changes
3. **User Notification**: Notify users of new device registrations
4. **Backup Codes**: Provide alternative access methods
5. **Privacy**: Hash sensitive fingerprint data

### Limitations

- Device fingerprinting can change with browser updates
- Users may lose access if all devices are lost
- Fingerprinting may be less reliable in incognito mode
- Some users may find it inconvenient
